Todo erro da API vem no mesmo formato:

```json
{
  "error": "invalid_input",
  "message": "Texto para mostrar à pessoa (às vezes)",
  "fields": { "answers.severity": ["Campo obrigatório"] },
  "data": {}
}
```

- **`error`**: o código, em inglês e `snake_case`. É ele que o seu código deve comparar; não mude de
  comportamento pelo texto.
- **`message`**: quando vem, é um texto em português para mostrar a quem usa.
- **`fields`**: no 400 `invalid_input`, cada campo inválido, com o caminho separado por ponto
  (`answers.severity`) e as mensagens em português. Erro no corpo inteiro (ex.: não é um objeto) vem na
  chave `_`. Nas rotas de login e cadastro, a mensagem do campo pode ser um código (ex.: `password_too_short`), e
  alguns erros vêm sem `fields` (ex.: 400 `invalid_cpf` no cadastro).
- **`data`**: contexto de alguns 409 (ex.: as entradas ativas que impedem a ação).

## no seu código

Compare sempre o `error`, e mostre a `message` quando ela vier:

```ts
const response = await fetch(url, init);
if (!response.ok) {
  const body = await response.json();
  switch (body.error) {
    case "invalid_input":
      // Marque cada campo de `body.fields` no formulário.
      break;
    case "not_authenticated":
      // A sessão venceu: volte para o login.
      break;
    default:
      // Mostre `body.message` quando vier; senão, uma mensagem genérica.
  }
}
```

## os status

| Status | Quando |
| --- | --- |
| 400 | Corpo, query ou parâmetro inválido (`invalid_input`), captcha da inscrição (`captcha_required`, `captcha_failed`) ou outro erro do login (`auth_error`) |
| 401 | Sem login (`not_authenticated`), login ou senha errados (`invalid_credentials`) ou TV não pareada (`tv_not_paired`) |
| 403 | Logado, mas sem permissão para a ação (`no_permission`) |
| 404 | Município desconhecido (`unknown_municipality`), recurso que não existe ou id malformado no caminho (`not_found`), código de TV errado (`invalid_code`) |
| 409 | A regra recusou a ação, e o código diz qual. Ex.: `duplicate` (a pessoa já tem inscrição nesse serviço), `no_slot`, `session_closed` |
| 422 | Falta escolher algo antes da ação (ex.: `classify_risk`, a cor da classificação de risco na triagem) |
| 429 | Muitas tentativas ([o que fazer](/docs/limites)) |
| 500 | Erro nosso (`internal_error`), sem detalhes na resposta |
| 503 | Serviço fora do ar por um momento (ex.: `captcha_unavailable`, `try_again`): tente de novo |

Cada rota da [referência](/docs/referencia) lista os códigos que pode devolver em cada status. As rotas de
login e cadastro não estão na referência; os códigos delas estão em [autenticação](/docs/autenticacao) e
[muitas tentativas](/docs/limites).
