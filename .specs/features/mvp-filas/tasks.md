# Tasks: MVP Filas UBS/Policlínicas

2026-11-10 · status: **backlog para revisão**

Origem: [plan.md](plan.md) (PD-01..PD-13), [source.md](source.md) (RN/US/INV) e AD-001..AD-048 em [STATE.md](../../STATE.md).

**Como ler.** Este arquivo é o backlog do MVP inteiro, em nível de task. Cada fase ganha um **plano detalhado de implementação** (arquivos, interfaces, testes e passos TDD) só quando vai começar, escrito sobre o código das fases anteriores. Uma task está pronta quando o critério dela passa, com testes, e foi revisada.

**TDD obrigatório em toda task.** Nenhum código de produção sem um teste falhando antes:

1. **Vermelho:** escrever o teste do próximo comportamento e rodar, vendo falhar pelo motivo certo (não por erro de import ou de digitação).
2. **Verde:** escrever o mínimo de código para esse teste passar.
3. **Refatorar** com todos os testes verdes; depois commit.

- O critério de pronto de cada task é provado por testes escritos nesse ciclo. Uma task sem teste falhando antes do código volta para o começo.
- Nas regras portadas do protótipo, o teste portado é o vermelho; nas regras novas (recorrência, permissões, AD-015..017, AD-020..048), o teste vem da regra da spec, com os dois lados de cada limite (L-004).
- Na API, o ciclo é pelo teste de integração da rota (padrão de `apps/api/tests/integration`); concorrência é testada com dois escritores reais (L-003).
- Em tela (painel e app), o teste cobre a lógica e o estado da tela; layout puro não precisa de teste.
- O plano detalhado de cada fase escreve os passos nesse formato: teste → rodar e ver falhar → implementar → rodar e ver passar → commit.

**Discoveries e spikes** (seção abaixo) rodam antes das tasks que dependem deles; os de campo correm em paralelo às fases 1 e 2.

**Ordem das fases:** 1 Fundação → 2 Configuração → 3 Fatia vertical da sessão pública → 4 Infra e deploy → 5 Sessão privada → 6 Triagem → 7 Recepção → 8 P2. A infra fica depois da primeira fatia rodando local (decisão de 2026-11-10); até lá, desenvolvimento no `compose.yml` atual.

**Testes do protótipo:** os 51 testes de `prototype/tests/engine.test.js` são reescritos em Vitest. As regras puras vão para `packages/domain` (fase 1). Os de TV, agenda e privacidade viram testes de API nas fases que constroem essas telas. `simulate` não é portado (é só da demo).
